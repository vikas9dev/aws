# AWS ELB & Auto Scaling - Handnote 📝

## 📊 SCALABILITY & HIGH AVAILABILITY

### Vertical Scaling (Scale Up/Down)
- Increase resources of **single instance**
- Example: `t2.micro` → `t2.large`
- Use for: **Non-distributed systems** (databases like RDS)
- ⚠️ Hardware limits exist

### Horizontal Scaling (Scale Out/In)
- Increase **number of instances**
- Also called **elasticity**
- Use for: **Distributed systems** (web applications)
- Achieved with: **Auto Scaling Groups + Load Balancers**

### High Availability
- Run application in **at least 2 data centers/AZs**
- **Passive**: RDS Multi-AZ (standby instance)
- **Active**: Multiple instances running simultaneously

## ⚖️ LOAD BALANCERS

### What are Load Balancers?
- **Distributed traffic** across multiple targets (EC2 instances, containers, IPs)
- **High availability** and fault tolerance by routing traffic only to healthy targets

### Why Use Load Balancers?
- ✅ Single point of access
- ✅ Automatic failure handling
- ✅ Health checks
- ✅ SSL termination
- ✅ Sticky sessions
- ✅ High availability across AZs
- ✅ Separate public/private traffic

### Types of Load Balancers

| Type | Layer | Protocols | Use Case |
|------|-------|-----------|----------|
| **CLB** (Classic) | 4 & 7 | HTTP, HTTPS, TCP, SSL | ⚠️ Deprecated |
| **ALB** (Application) | 7 | HTTP, HTTPS, WebSocket | HTTP-based apps, microservices |
| **NLB** (Network) | 4 | TCP, TLS, UDP | High performance, static IPs |
| **GWLB** (Gateway) | 3 | IP | Third-party network appliances |

## 🌐 APPLICATION LOAD BALANCER (ALB)

### What is ALB?
- **Layer 7 load balancer** for HTTP/HTTPS traffic with advanced routing capabilities
- **Content-based routing** using path, hostname, headers, and query strings

### Features
- ✅ **Layer 7** (HTTP/HTTPS)
- ✅ **Target Groups**: EC2, ECS, Lambda, IP addresses
- ✅ **Advanced Routing**: Path, hostname, query strings, headers
- ✅ **HTTP/2 & WebSocket** support
- ✅ **Redirects** (HTTP → HTTPS)
- ✅ **Fixed hostname**: `XX.region.elb.amazonaws.com`

### Client IP Address
- Client IP in **`X-Forwarded-For`** header
- Port in **`X-Forwarded-Port`** header
- Protocol in **`X-Forwarded-Proto`** header

### ALB Rules
- **Priority**: 1-50,000 (lower = higher priority)
- **Conditions**: Host header, path, HTTP method, source IP, query string, headers
- **Actions**: Forward, redirect, fixed response

### Security Best Practice
- **EC2 Security Group**: Allow HTTP **only from ALB Security Group**
- **ALB Security Group**: Allow HTTP/HTTPS from `0.0.0.0/0`

## ⚡ NETWORK LOAD BALANCER (NLB)

### What is NLB?
- **Layer 4 load balancer** for TCP, TLS, and UDP traffic with ultra-low latency
- **Static IP addresses** and ability to handle millions of requests per second

### Features
- ✅ **Layer 4** (TCP/UDP)
- ✅ **High performance**: Millions of requests/sec
- ✅ **Ultra-low latency**
- ✅ **Static IP per AZ** (can assign Elastic IP)
- ✅ **Target Groups**: EC2, IP addresses (private), ALBs (not Lambda — only ALB supports Lambda targets)

### Use Cases
- Extreme performance requirements
- TCP/UDP traffic
- **Static IP addresses** needed
- Gaming servers, real-time streaming

### Health Checks
- Supports: **TCP, HTTP, HTTPS**
- Can use HTTP/HTTPS even for TCP listeners

### NLB in Front of ALB
- **NLB**: Provides fixed IPs
- **ALB**: Provides HTTP routing
- **Combination**: Best of both worlds

## 🚪 GATEWAY LOAD BALANCER (GWLB)

### What is GWLB?
- **Layer 3 load balancer** for deploying and managing third-party network virtual appliances
- **Transparent network gateway** that distributes traffic to security appliances (firewalls, IDPS)

### Purpose
- Deploy, scale, manage **third-party network virtual appliances**
- Firewalls, IDPS, deep packet inspection

### How It Works
1. All VPC traffic goes through GWLB
2. GWLB distributes to virtual appliances
3. Appliances analyze traffic
4. Approved traffic returns through GWLB to application

### Features
- **Layer 3** (IP protocol)
- **GENEVE protocol on port 6081**
- **Transparent Network Gateway** + **Load Balancer**
- **Target Groups**: EC2 instances, IP addresses (private)

## 🍪 STICKY SESSIONS (Session Affinity)

### Purpose
- Route same client to **same backend instance**
- Prevents session data loss

### Cookie Types
1. **Application-Based Cookies**: Custom cookie from application
2. **Duration-Based Cookies**: Cookie generated by load balancer

### Considerations
- ⚠️ Can cause **load imbalance**
- ⚠️ **NLB works without cookies** (uses source IP)

### Supported By
- Classic Load Balancer
- Application Load Balancer
- Network Load Balancer

## 🔄 CROSS-ZONE LOAD BALANCING

### ALB
- ✅ **Always enabled** (cannot disable)
- ✅ No additional cost

### NLB
- ⚠️ **Disabled by default**
- ⚠️ **$0.01/GB** for cross-AZ data transfer if enabled
- ✅ Enable for better load distribution

### CLB
- ⚠️ **Disabled by default**
- ✅ Free if enabled

## 🔒 SSL/TLS CERTIFICATES

### Integration
- **ACM (AWS Certificate Manager)**: Free public certificates
- **IAM**: Upload your own certificates
- **SNI (Server Name Indication)**: Multiple certificates per listener

### SSL Termination
- Load balancer handles SSL/TLS
- Backend receives unencrypted traffic (unless using end-to-end encryption)

## ⏱️ CONNECTION DRAINING / DEREGISTRATION DELAY

### Purpose
- Allow **in-flight requests to complete** before instance removed
- **1-3600 seconds** (default: 300 seconds)

### How It Works
1. Instance marked unhealthy
2. Load balancer stops sending new requests
3. Waits for draining period
4. Completes in-flight requests
5. Removes instance

## 📈 AUTO SCALING GROUPS (ASG)

### Purpose
- **Automatically scale** EC2 instances based on demand
- **High availability** across multiple AZs
- **Replace unhealthy instances**

### Components
- **Launch Template/Configuration**: AMI, instance type, security groups, user data
- **Min Size**: Minimum number of instances
- **Max Size**: Maximum number of instances
- **Desired Capacity**: Target number of instances
- **Health Checks**: EC2 status checks, ELB health checks

### Scaling Policies

#### Target Tracking Scaling
- Maintain target metric value
- Example: Keep CPU at 50%

#### Simple/Step Scaling
- Scale based on CloudWatch alarms
- Example: Add 2 instances if CPU > 70%

#### Scheduled Scaling
- Scale at specific times
- Example: Scale up at 9 AM, scale down at 5 PM

### Scaling Cooldowns
- **Default Cooldown**: 300 seconds (simple scaling only; target tracking and step scaling use instance warm-up)
- Prevents rapid scaling up/down
- **Instance Warmup**: Time for new instance to be ready

### Health Checks
- **EC2 Status Checks**: Default, checks instance health
- **ELB Health Checks**: Optional, checks application health
- **Health Check Grace Period**: Time before unhealthy instances replaced

### Lifecycle Hooks
- **Launching**: Actions before instance enters service
- **Terminating**: Actions before instance terminates
- Use with: **Lambda, SNS, SQS**

## ⚠️ CRITICAL EXAM POINTS

1. **ALB**: Layer 7, HTTP/HTTPS, advanced routing, always cross-zone enabled
2. **NLB**: Layer 4, TCP/UDP, static IPs, cross-zone disabled by default ($)
3. **GWLB**: Layer 3, IP protocol, GENEVE port 6081, network appliances
4. **Sticky Sessions**: Can cause load imbalance
5. **Cross-Zone**: ALB always on, NLB off by default ($)
6. **Target Groups**: ALB (EC2, ECS, Lambda, IP), NLB (EC2, IP, ALB — no Lambda)
7. **Health Checks**: Required for load balancers to work
8. **ASG**: Min/Max/Desired capacity, scaling policies, health checks
9. **Security Groups**: EC2 should only allow traffic from LB SG
10. **Client IP**: Use `X-Forwarded-For` header (ALB)

## 📋 QUICK REFERENCE

### Choosing Load Balancer
- **HTTP/HTTPS apps**: ALB
- **High performance, static IPs**: NLB
- **Network appliances**: GWLB
- **Legacy apps**: CLB (deprecated)

### ASG Best Practices
- Use **multiple AZs** for high availability
- Configure **health checks** (EC2 + ELB)
- Set appropriate **cooldown periods**
- Use **launch templates** (not launch configurations)
- Enable **detailed monitoring** for faster scaling

### Security Best Practice
```
Internet → ALB (SG: Allow 80/443 from 0.0.0.0/0)
         ↓
    EC2 Instances (SG: Allow 80 from ALB SG only)
```
